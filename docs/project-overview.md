# プロジェクト概要

## これは何か

**TypeScript でバックエンドを作れるようになるための、12週間の学習プロジェクト**です。
題材は `Repository Provisioning Service`(GitHub リポジトリの作成・管理を行う小さなバックエンドアプリ)です。

文法を覚えるだけでなく、次のことを**自分の力で**できるようになることが目的です。

- 要件を整理し、構成と責務を設計する
- TypeScript の型システムで、型安全なコードを書く
- 外部API(GitHub)との連携、非同期処理、エラーハンドリングを設計する
- テストを設計し、自分の実装の品質を自分で検証する
- セキュリティのリスクを理解し、コードと開発プロセスに対策を組み込む
- GitHub Actions で品質を自動で担保する
- 設計意図とトレードオフを説明する

## このプロジェクトの方針

**AI(や完成形)にコードを書いてもらうのが目的ではありません。** 完成形の実装は用意してありますが、それは「答え合わせ」用です。
あなたは同じ要求仕様を読み、`starter/` に**自分で**設計・実装します。

AI は、次の用途で使います(Claude Code が使えなくなった後も、`docs/` を読めば学習を続けられます)。

| 使う                                    | 使わない                         |
| --------------------------------------- | -------------------------------- |
| 技術的な疑問の解消 / 設計方針の相談     | 課題の実装を丸ごと書いてもらう   |
| コードレビュー / 自分の設計への改善提案 | 完成形(`reference/`)をコピーする |
| テスト方針の相談 / 複数の実装方法の比較 |                                  |
| エラーの原因調査                        |                                  |

## 作るもの

```
クライアント ──HTTP──▶ Repository Provisioning Service ──HTTPS──▶ GitHub API
                              │
                              └──▶ SQLite(要求と結果を保存)
```

1. クライアントが「こういうリポジトリを作って」と HTTP で要求する(`POST /v1/repository-requests`)
2. 入力を検証し、要求を SQLite に保存する
3. GitHub API でリポジトリを作成する(タイムアウト・リトライ・重複防止つき)
4. 結果を保存して返す。あとから `GET` で状態・結果を参照できる

シンプルに保ちつつ、実務でも重要になる要素(冪等性・障害時の復旧・秘密情報の扱い・テスト容易性)を含めています。
