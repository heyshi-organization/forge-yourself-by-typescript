# 用語集

## このプロジェクトの用語

| 用語                                                     | 意味                                                                                                     |
| -------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| **作成要求(Provisioning Request / `RepositoryRequest`)** | 「このリポジトリを作って」という1回の要求と、その処理状態・結果をまとめたもの。DBの1行。IDは `requestId` |
| **相関ID(`correlationId`)**                              | HTTPリクエスト1回ごとのID。ログとレスポンス(`X-Correlation-Id`)に出る。`requestId`(作成要求のID)とは別物 |
| **spec(`RepositorySpec`)**                               | 作りたいリポジトリの仕様(owner・name・visibility…)。入力検証済みの値                                     |
| **状態(status)**                                         | `PENDING`(受付済み)/ `PROCESSING`(処理中)/ `SUCCEEDED`(成功)/ `FAILED`(失敗)。後ろの2つが**終端状態**    |
| **ポート**                                               | 外部との境界を表すインターフェース(`GitHubClient`, `RequestRepository`, `RepositoryProvisioner`)         |
| **アダプタ**                                             | ポートの実装(`OctokitGitHubClient`, `SqliteRequestRepository`, `FakeGitHubClient` など)                  |
| **Composition Root**                                     | 依存関係を組み立てる唯一の場所(`composition.ts`)                                                         |
| **リース(lease)**                                        | `PROCESSING` のまま、この時間を超えた要求を「処理が中断された」とみなす時間(`PROCESSING_LEASE_MS`)       |
| **reconcile(突き合わせ)**                                | 中断された要求について、GitHub の実際の状態を見て、結果を確定させること                                  |
| **曖昧な失敗(ambiguous)**                                | タイムアウトなど、**処理が実行されたのか分からない**失敗                                                 |
| **reference / starter**                                  | 完成形 / 学習者が実装する未完成コード                                                                    |
| **受け入れテスト**                                       | 課題の「完了条件」を機械的に検証するテスト(`exercises/tests/`)                                           |
| **ミュータント**                                         | わざとバグを仕込んだ実装。テストの強さを測るために使う                                                   |
| **security-labs / lab-workspace**                        | 意図的に脆弱なコードを使う演習 / その展開先(`exercise/*` ブランチにだけ存在)                             |

## TypeScript / 型

| 用語                                   | 意味                                                                                                           |
| -------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| **Union型(`A \| B`)**                  | A または B                                                                                                     |
| **判別可能Union(Discriminated Union)** | 共通のリテラル型のフィールド(`status`)で、どの型か判別できる Union。`if (x.status === 'FAILED')` で絞り込める  |
| **Type Narrowing(絞り込み)**           | 条件分岐で、型をより具体的な型にすること                                                                       |
| **ジェネリクス(`<T>`)**                | 型を引数として受け取る仕組み。`Result<T, E>` のように、中身の型に関わらず使える                                |
| **Utility Types**                      | `Partial<T>`・`Pick<T,K>`・`Record<K,V>`・`Extract<T,U>`・`ReturnType<T>` など、型から型を作る標準の型         |
| **型推論**                             | 書かなくても、コンパイラが型を決めること                                                                       |
| **`unknown` と `any`**                 | `any` は何でも許す(型チェックを無効化)。`unknown` は「分からない」ので、使う前に絞り込みが必要(安全)           |
| **型アサーション(`as`)**               | 「この型だ」と**主張**するだけ。実行時には何も検査しない(検証ではない)                                         |
| **`satisfies`**                        | 型に適合するか検査しつつ、推論された具体的な型を保つ                                                           |
| **`never`**                            | 到達しない型。網羅性チェック(`assertNever`)に使う                                                              |
| **`readonly`**                         | 再代入できない                                                                                                 |
| **ESM**                                | JavaScript のモジュール方式(`import`/`export`)。このプロジェクトは ESM。相対 import には拡張子(`./a.js`)が必要 |

## 非同期

| 用語                                  | 意味                                                                                                      |
| ------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| **Promise**                           | 将来の結果(成功/失敗)を表すオブジェクト                                                                   |
| **`async` / `await`**                 | Promise を同期的な見た目で書く構文                                                                        |
| **イベントループ**                    | Node.js が、待ち行列のコールバック/Promise を1つずつ実行する仕組み。`await` のたびに他の処理が割り込める  |
| **`AbortController` / `AbortSignal`** | 非同期処理(fetch など)を中断する仕組み                                                                    |
| **タイムアウト**                      | 一定時間で諦めること                                                                                      |
| **指数バックオフ**                    | 失敗のたびに待ち時間を倍にしていくこと                                                                    |
| **Jitter(ジッター)**                  | 待ち時間に乱数を混ぜ、複数のクライアントの再試行が揃うのを防ぐこと。**Full Jitter** は 0〜上限 の一様乱数 |
| **Retry-After**                       | サーバーが「◯秒後に再試行して」と指示するHTTPヘッダ                                                       |
| **レート制限(Rate Limit)**            | 一定時間あたりのリクエスト数の制限(GitHub は 403/429 + ヘッダで通知)                                      |

## 設計・信頼性

| 用語                              | 意味                                                                                    |
| --------------------------------- | --------------------------------------------------------------------------------------- |
| **冪等(idempotent)**              | 同じ操作を何回行っても、結果が1回行ったのと同じになること                               |
| **Idempotency-Key**               | クライアントが付ける、要求の識別子。同じキー = 同じ要求とみなす                         |
| **compare-and-set(楽観的ロック)** | 「今が期待どおりの状態なら更新する」を1操作で行う。`UPDATE ... WHERE status = ?`        |
| **トランザクション**              | 複数のDB操作を、全部成功か全部取り消しにまとめる仕組み                                  |
| **部分ユニークインデックス**      | 条件(`WHERE`)を満たす行だけに一意性を課すインデックス                                   |
| **DI(依存性の注入)**              | 必要な依存を、自分で作らず外から渡してもらうこと                                        |
| **Fake / Stub / Mock**            | テスト用の代役。Fake=簡易だが動く実装 / Stub=決まった値を返す / Mock=呼ばれ方を検証する |
| **契約テスト**                    | 同じインターフェースの複数の実装に、同じテストを実行すること                            |
| **Property-based Testing**        | 例ではなく「性質」を書き、入力を自動生成して検証するテスト                              |
| **ミューテーションテスト**        | コードに小さなバグを仕込み、テストが検出できるかで、テストの強さを測る手法              |
| **相関ID**                        | 1つの処理に関するログを結びつけるID                                                     |
| **構造化ログ**                    | JSON など機械が読める形式のログ                                                         |

## セキュリティ

| 用語                                  | 意味                                                                                |
| ------------------------------------- | ----------------------------------------------------------------------------------- |
| **SAST**                              | ソースコードを静的に解析して脆弱性を見つける(CodeQL)                                |
| **SCA**                               | 依存パッケージの既知の脆弱性・ライセンスを調べる(`npm audit`, Dependency Review)    |
| **CodeQL**                            | GitHub のコード解析エンジン。コードをデータベース化し、クエリで脆弱性パターンを探す |
| **taint tracking(汚染追跡)**          | 外部入力(source)から危険な処理(sink)までデータが流れるかを追跡する解析              |
| **False Positive / False Negative**   | 誤検知(問題でないのに検出)/ 見逃し(問題なのに検出しない)                            |
| **SQLインジェクション**               | 入力がSQLの構造として解釈されてしまう脆弱性。対策: バインド変数                     |
| **コマンドインジェクション**          | 入力がシェルのコマンドとして解釈される脆弱性。対策: シェルを介さない・引数配列      |
| **パストラバーサル**                  | `../` などで、意図しないファイルを指す脆弱性                                        |
| **SSRF**                              | サーバーに、意図しないURL(内部ネットワーク等)へリクエストさせる脆弱性               |
| **IDOR / Broken Access Control**      | IDを変えるだけで他人のデータにアクセスできる(認可の欠如)                            |
| **Mass Assignment**                   | クライアントが、設定させるべきでない項目(権限・状態)まで指定できてしまう            |
| **Secret Scanning / Push Protection** | リポジトリ内の秘密情報を検出 / 秘密情報を含む push をブロック                       |
| **Dependabot**                        | 依存の更新・脆弱性修正のPRを自動で作る                                              |
| **SHA固定**                           | GitHub Actions を、書き換えられるタグでなくコミットSHAで指定すること                |
| **最小権限**                          | 必要最小限の権限だけを与えること(`permissions`)                                     |
