# ADR-0016: APIの範囲(認証なし)と OpenAPI

- 状態: 採用
- 日付: 2026-11-25

## 決定1: このAPIに認証・認可は設けない(ローカル専用)

- 要件では「ローカルPC上のNode.jsプロセス」として動かし、「ローカル環境以外に不用意に公開しない設定」が求められている
- そのため、**既定で `127.0.0.1` にだけバインド**し、`HOST` に他の値を指定すると、`ALLOW_PUBLIC_BIND=true` を明示しない限り起動を拒否する(`schemas/config.ts`、テストあり)
- 認証なしで公開すると、誰でも**サービスのGitHubトークンの権限でリポジトリを作れてしまう**。公開する場合は、前段に認証(リバースプロキシ・APIキー・OIDC 等)が必須
- 認可(IDOR等)の学習は、セキュリティ演習07で別途扱う

## 決定2: OpenAPI は Zod のスキーマから生成する

- `GET /openapi.json` で配信。`docs/openapi.json` にも保存し、**コードと食い違ったらテストが失敗**する(`npm run docs:openapi` で更新)
- リクエストのスキーマは Zod → `z.toJSONSchema()`。エラーコード一覧は `ERROR_CATALOG` から。レスポンスの形は手書き(公開してよい項目を明示するため)
- 仕様書に載っているルートが実在することをテストで確認する

## 決定3: URL設計

- バージョンを URL に含める(`/v1/...`)。破壊的変更のときだけ `/v2` を追加する
- リソース名: `repository-requests`(作成要求)。作成 = `POST`、参照 = `GET`
- `Idempotency-Key` はヘッダ。必須(付け忘れが重複作成につながるため、省略を許さない)
