# ADR-0010: SQLite のスキーマ設計

- 状態: 採用
- 日付: 2026-11-25

詳細は [docs/database-design.md](../database-design.md)。判断だけを記録する。

## 決定と理由

| 判断                                                                                                  | 理由                                                                                                               |
| ----------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| `STRICT` テーブル                                                                                     | SQLiteは既定で型に緩い(INTEGER列に文字列が入る)。型の不一致をDBで検出する                                          |
| `CHECK` 制約(status の値、status と各列の整合)                                                        | アプリのバグがあっても、**ありえない行**(SUCCEEDED なのに GitHub情報が無い 等)が保存されない                       |
| `idempotency_key` の `UNIQUE`                                                                         | 冪等性の最後の砦(ADR-0007)                                                                                         |
| 部分ユニークインデックス `(owner, repo_name) WHERE status IN ('PENDING','PROCESSING') COLLATE NOCASE` | 同じリポジトリへの処理中の要求を1件に制限。終了後は再挑戦できる。GitHubの名前は大文字小文字を区別しないので NOCASE |
| spec を列に展開(JSONにしない)                                                                         | 制約・インデックス・検索に使える。topics/warnings だけは配列なので JSON(`json_valid` で検査)                       |
| 日時は ISO 8601 文字列(UTC)                                                                           | 文字列の大小比較が時系列の比較になる。SQLiteに日時型は無い                                                         |
| `journal_mode=WAL` / `busy_timeout=5000`                                                              | 読み書きが互いをブロックしにくい / ロック競合時に即エラーにせず待つ                                                |
| マイグレーションは番号付きSQL(`schema_migrations` テーブルで管理、1件ごとにトランザクション)          | ツールを増やさず、仕組みを理解できる。適用済みは書き換えず、変更は新しい番号で追加                                 |
| SQLは**必ずバインド変数**                                                                             | SQLインジェクション対策(セキュリティ演習01)                                                                        |
| 取得時に行を判別可能Union型へ変換し、必須列がNULLなら `PersistenceError`                              | DBの不整合を握りつぶさない                                                                                         |

## トランザクションを使う場所

- `createOrGet`(SELECT → INSERT を原子的に)
- `transition`(UPDATE → SELECT)
- マイグレーション(1件ごと)
