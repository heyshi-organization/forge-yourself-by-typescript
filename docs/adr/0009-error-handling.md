# ADR-0009: エラー処理方針

- 状態: 採用
- 日付: 2026-11-25

## 決定

### 1. 利用者に返すものと、内部に残すものを分ける

|          | 利用者(HTTPレスポンス / DBに保存)                           | 内部(ログのみ)                                                                    |
| -------- | ----------------------------------------------------------- | --------------------------------------------------------------------------------- |
| 内容     | エラーコード + 定型メッセージ + 相関ID(+入力エラーの項目名) | 例外オブジェクト(スタックトレース・cause)、GitHubのレスポンス、試行回数、所要時間 |
| 出どころ | `errors/catalog.ts`(エラーカタログ)                         | `logger.warn/error({ err })`                                                      |

- DBの `error_message` には**カタログの定型メッセージだけ**を保存する(内部の詳細は保存しない)
- 想定外の例外(`TypeError` など)は、HTTP層で `INTERNAL_ERROR`(500)に変換する。メッセージは返さない
- 入力エラーは「どの項目が・なぜ」だけを返し、**入力値そのものは返さない**(秘密の反射を避ける)
- 利用者が問い合わせるときのために、`correlationId`(HTTPリクエスト単位)と `requestId`(作成要求単位)を返す

### 2. HTTPステータスの割り当て

| 状況                                                    | ステータス | 補足                                                                                                            |
| ------------------------------------------------------- | ---------- | --------------------------------------------------------------------------------------------------------------- |
| 入力不正 / Idempotency-Key不正                          | 400        |                                                                                                                 |
| 存在しない                                              | 404        |                                                                                                                 |
| 同名リポジトリが存在 / 処理中                           | 409        |                                                                                                                 |
| 同じキーで内容が違う / GitHubが内容を拒否 / owner不一致 | 422        |                                                                                                                 |
| **GitHub の認証エラー・権限不足**                       | **502**    | クライアントの責任ではなく、サービス側の設定の問題。401/403にするとクライアントが「自分の認証が悪い」と誤解する |
| レート制限・一時障害                                    | 503        | 別の Idempotency-Key で再試行を促す                                                                             |
| GitHub のタイムアウト                                   | 504        |                                                                                                                 |
| 処理の中断・内部エラー                                  | 500        |                                                                                                                 |

### 3. 失敗の表現

- 例外(throw): 想定外・プログラムのバグ・DB障害 → エラーハンドラが一括で処理する
- `Result<T, E>`(値): 「起こりうる失敗」。`RepositoryProvisioner` が `Result` を返し、呼び出し側が分岐を**型で強制される**

### 4. 保存の失敗

結果の保存に失敗したら例外にして、要求は `PROCESSING` のまま残す(ADR-0007の復旧が拾う)。
その際、**GitHub上に作られたリポジトリ名をログに残す**(復旧の手がかり)。

## 結果

エラーコードの追加は `errors/catalog.ts` の1行 + OpenAPIとテストの更新だけで済む(OpenAPIはカタログから生成)。
