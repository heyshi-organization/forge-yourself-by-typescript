# ADR-0001: 技術選定

- 状態: 採用
- 日付: 2026-11-25

## 背景

TypeScript によるバックエンド開発を学ぶための教材として、(1) 学習対象(TypeScriptの設計・実装・テスト)に時間を使える、
(2) ローカルの Node.js だけで完結する、(3) 実務でも通用する、の3点を満たす構成を選ぶ。
実装開始時(2026-11-25)に `npm view` で各ライブラリの現行バージョンと対応 Node.js を確認した。

## 決定

| 領域           | 採用                                       | バージョン(確認時点)          | 選定理由                                                                                                                              |
| -------------- | ------------------------------------------ | ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| 実行環境       | Node.js                                    | 24.19(LTS系。`.nvmrc` で固定) | 本リポジトリのワークスペース標準。`process.loadEnvFile` など、環境変数読み込みが標準で使える                                          |
| 言語           | TypeScript                                 | **6.0.3**                     | 下記「TypeScript 7 を採用しなかった理由」                                                                                             |
| HTTP           | Fastify                                    | 5.12                          | スキーマ・フック・`inject()`(ネットワーク不要のテスト)が揃い、Pino ログが標準で組み込まれている                                       |
| 入力値検証     | Zod                                        | 4.6                           | スキーマから `z.infer` で型を導出でき、**型と実行時検証が二重管理にならない**(学習目的に合う)。`z.toJSONSchema` でOpenAPIも生成できる |
| GitHub API     | `@octokit/rest`                            | 22.0                          | GitHub公式のクライアント。型付きでレスポンス・エラー(`RequestError`)が扱える                                                          |
| DB             | SQLite(`better-sqlite3`)                   | 13.2                          | 下記「SQLite ライブラリ」                                                                                                             |
| テスト         | Vitest                                     | 5.1                           | TypeScript をそのまま実行でき高速。型テスト(`expectTypeOf`)・カバレッジ(v8)も標準                                                     |
| Property-based | fast-check                                 | 4.11                          | 「どんな入力でも成り立つ性質」を書く練習のため                                                                                        |
| Lint / Format  | ESLint 10(typescript-eslint 8)/ Prettier 3 |                               | 型情報を使った lint(`no-floating-promises` 等)で非同期のバグを防ぐ                                                                    |
| ログ           | Pino                                       | 10                            | Fastify 標準。構造化ログ(JSON Lines)                                                                                                  |
| TS実行(開発用) | tsx                                        | 4                             | 開発時の起動・スクリプト用。本番相当は `tsc` でビルドして `node` で実行                                                               |

### TypeScript 7 を採用しなかった理由(事実)

`npm view typescript` の最新は 7.0.2 だが、`typescript-eslint@8.74.0` の peer 依存は `typescript >=4.8.4 <6.1.0` で、
**7 系は未対応**(2026-11-25 時点)。型情報つき lint を使いたいので、対応範囲の最新である **6.0.3** に固定した。
typescript-eslint が 7 に対応したら更新する(Dependabot の PR で気づける)。

### SQLite ライブラリ: `better-sqlite3` を選んだ理由

| 選択肢                            | メリット                                                                                                                 | デメリット                                               |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------- |
| `better-sqlite3`                  | 同期APIでトランザクションが書きやすい。実績が多い。13系は**プリビルドバイナリを同梱**しており、install script なしで動く | ネイティブアドオン                                       |
| `node:sqlite`(Node 標準)          | 依存ゼロ                                                                                                                 | 本リポジトリの対象 Node では実験的機能(API が変わりうる) |
| `sqlite3` + ORM(Prisma/Drizzle等) | 型付きクエリ                                                                                                             | 学習対象でない技術(ORM)に時間を使う。SQLの理解が浅くなる |

→ **SQL を自分で書いて理解する**ことも学習目的なので、素の `better-sqlite3` を採用。`npm ci --ignore-scripts` でも動くのでサプライチェーン面でも有利。
(Repository インターフェースで隠しているので、後から差し替えられる)

### 採用しなかったもの

- Docker / Kubernetes / メッセージキュー / ORM / DIコンテナ: 学習対象でなく、複雑さが増えるだけ(要件の「技術選定の原則」)

## 結果

- 全員が同じバージョンで動かせる(`package-lock.json` + `.nvmrc`)。更新は Dependabot が PR で提案する
- TypeScript の更新は typescript-eslint の対応状況に縛られる(受け入れるトレードオフ)
