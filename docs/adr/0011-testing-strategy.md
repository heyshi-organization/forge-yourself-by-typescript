# ADR-0011: テスト戦略

- 状態: 採用
- 日付: 2026-11-25

詳細は [docs/testing-strategy.md](../testing-strategy.md)。判断だけを記録する。

## 決定

1. **通常のテスト(`npm test`)は、ネットワーク・認証情報なしで動く**。GitHub は Fake(`FakeGitHubClient`)に差し替える
2. **実GitHub通信のテスト(ライブテスト)は別コマンド**(`npm run test:live`)で、複数の環境変数が揃わない限り何もしない(誤ってリポジトリを作らない)
3. **Fake を自前で用意**し、HTTPレベルのモックライブラリ(msw / nock)は使わない
   - 理由: ビジネスロジックのテストでは「GitHubClient の挙動(失敗の仕方)」を指定したい。HTTPの形は `OctokitGitHubClient` のテストだけで、`fetch` を差し替えて検証する(2層に分けることで、どちらも小さく保てる)
4. **契約テスト**: `InMemoryRequestRepository` と `SqliteRequestRepository` に**同じテスト**を実行する。Fake が本物と食い違わないことの保証
5. **Property-based Testing**(fast-check): 状態遷移・バックオフ・名前検証・秘密マスクのように「どんな入力でも成り立つ性質」があるもの
6. **異常系を網羅する**: 認証エラー・権限不足・レート制限・タイムアウト・一時障害・DB保存失敗・重複・リトライ超過(要件8.4)
7. **カバレッジは閾値で下限を守る**(行90%/分岐85%)が、目的は数字ではない。**「テストが本当にバグを検出できるか」をミューテーション検査(課題07)で確認する**
8. **型もテストする**(`expectTypeOf`): 課題01・02・04は型が学習対象

## 結果

- 速度: 全テストが数秒で終わる(外部I/Oなし)
- ライブテストは、安全のため手動・任意。CIでは実行しない(秘密情報をCIに渡さない)
