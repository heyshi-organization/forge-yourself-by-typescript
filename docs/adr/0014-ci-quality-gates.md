# ADR-0014: CI の品質ゲート

- 状態: 採用
- 日付: 2026-11-25

詳細は [docs/ci-cd.md](../ci-cd.md)。

## 決定: 何で PR を失敗させるか

| 検査                                                                           | 失敗条件                                       | 理由                                                                                                   |
| ------------------------------------------------------------------------------ | ---------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| 型検査(reference / starter)                                                    | エラー1件でも                                  | 型エラーは確実にバグ                                                                                   |
| ESLint                                                                         | **エラー**(警告は許容)                         | 警告は個別に判断する。starter は未実装由来の警告があるので警告扱い                                     |
| Prettier                                                                       | 差分があれば                                   | 議論の余地がない                                                                                       |
| テスト + カバレッジ                                                            | 失敗、または閾値(行90%・分岐85%)未満           | 異常系を含めて検証されていること                                                                       |
| 受け入れテスト(完成形) / ミューテーション自己検証 / 演習の健全性 / starter同期 | 失敗                                           | 教材が壊れていないこと                                                                                 |
| ワークフロー検査                                                               | 違反1件でも                                    | 権限・SHA固定・インジェクションは「守るか守らないか」                                                  |
| 秘密情報スキャン                                                               | 検出1件でも                                    | 公開リポジトリ                                                                                         |
| **`npm audit`(本番依存)**                                                      | **High 以上**(`--omit=dev --audit-level=high`) | 実際に配布・実行される依存の重大な脆弱性                                                               |
| npm audit(開発依存を含む)                                                      | **失敗させない**(サマリに表示)                 | 開発専用ツールの Moderate でマージを止めると運用できない。Dependabot が更新PRを出す                    |
| **Dependency Review**                                                          | **High 以上**かつ runtime スコープ             | PR で**新たに持ち込む**脆弱な依存を止める(既存の負債でPRを全部止めない)                                |
| CodeQL                                                                         | 解析自体の失敗                                 | 検出結果(アラート)は Security タブで**トリアージ**する。Severity に応じて対応(docs/security-design.md) |

- 「すべての警告を無条件に失敗」にはしない。失敗にするのは、**誤検知が少なく、直す責任が PR 作成者にあるもの**
- `starter-progress`(課題の進捗)は `continue-on-error`。未実装なのは正常な状態

## Actions のサプライチェーン

- すべての Action を**コミットSHAで固定**(タグは付け替え可能)。コメントに元のバージョンを書く。更新は Dependabot(`github-actions`)が PR で提案する
- 第三者製 Action は使っていない(公式の `actions/*` と `github/codeql-action` のみ)
- `npm ci --ignore-scripts`(依存の install script を実行しない)
- `persist-credentials: false`(checkout したトークンを `.git` に残さない)
- 検査の自動化: `scripts/check-workflows.mjs`

## ブランチ保護

GitHub 側の設定が必要なため、手順を [docs/github-settings.md](../github-settings.md) に記載(リポジトリの設定は自動変更していない)。
